# 支付主链路回归矩阵（2026-08-09）

本文档用于把当前 `test` 基线下的主链路回归项固定为可重复执行的回归包，避免后续版本只验证接口成功而遗漏金额、状态、事件、页面和回滚口径。

当前版本定位：

- 分支：`test`
- 日期：`2026-08-09`
- 版本状态：可继续迭代，不可直接切 `master` / `release`

## 4. 当前高优先级缺口

### 4.1 页面证据缺口

1. `admin-web / app-web / h5-web / pc-web` 的最新冻结截图还未和当前代码基线一一绑定。
2. 目前更多是接口与测试通过证据，页面级验收仍不足以支撑正式冻结交付。

### 4.2 补偿证据缺口

1. 补偿能力本身已存在，但缺少“最新同批次” replay / retry / DLQ / 人工结案完整归档。
2. 这意味着系统更接近“具备能力”，还不到“可以发版冻结”。

### 4.3 发布治理缺口

1. 缺少基于当前 `test` 基线的正式候选发布说明。
2. 缺少真实回滚演练、观察期和签字证据。

## 5. 下一轮自动推进顺序

1. 先补 `REG-08` 的最新同批次补偿闭环证据。
2. 再补 `REG-01 ~ REG-10` 对应页面冻结截图与页面矩阵映射。
3. 再生成基于当前基线的候选发布说明，重新判断是否允许合并 `master`。

## 6. 自动化判定规则

只有同时满足以下条件，才允许从 `test` 自动进入 `master`：

1. 关键后端门禁全部通过
2. 关键前端构建与页面冻结验收通过
3. 真实隔离环境主链路、补偿链路、回滚链路均有最新同批次证据
4. 候选发布说明、回滚方案、观察结果和签字结论齐全

只有 `master` 满足上述条件并稳定后，才允许切 `release/*`。
