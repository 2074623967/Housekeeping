## 3. 分支判定

### 3.1 `feature/* -> test`

当前允许进入 `test`，依据如下：

1. 六个系统的后端自动化测试均已通过。
2. 九个前端构建目标均已通过。
3. 各系统已具备本轮自测记录，跨系统 smoke 结果已沉淀到《跨系统联调与 Smoke 测试记录》。
4. 已验证 `支付成功事件 -> 清分 -> 结算 -> 账务入账` 的事件契约和消费结果。
5. 本轮改动已执行 `git diff --check`。

### 3.2 `test -> master / release`

当前仍禁止进入 `master` 或创建 `release/*`，原因如下：

1. 跨系统 smoke 当前使用显式事件投递，尚未验证生产级 MQ 自动发布、自动消费、重试、死信和补偿。
2. 尚未完成 `test` 分支上的整包复验和稳定观察。
3. 整包数据库建库建表、跨系统失败补偿和真实支付成功事件自动投递仍需继续验证。

## 4. 下一步门禁计划

1. 合入 `test`，在 `test` 分支重新执行全量构建、后端测试和跨系统 smoke。
2. 补支付成功事件自动投递到清分系统的适配能力，并覆盖失败重试、幂等、死信和补偿。
3. 执行整包数据库初始化与关键链路 smoke test。
4. `test` 稳定后再评估 `master` 合并与 `release/*` 发布文档。
