# 回归证据包使用说明

## 1. 目的

本说明用于配合 `PA-20260809-05`，把支付主链路回归从“零散测试记录”升级为“统一证据包 + 统一门禁审计”。

回归证据包和冻结证据包的区别：

1. 回归证据包强调主链路、数据库事实、事件台账、页面状态和补偿/回滚的统一场景归档。
2. 冻结证据包强调页面截图和最终冻结前的人工作业归档。
3. 回归证据包通过后，只说明更接近 `test -> master`；不代表已经满足正式切版条件。

## 2. 初始化命令

```bash
tools/release/init_regression_evidence_pack.sh test-20260809-regression 2026-08-09
```

生成目录：

```text
docs/releases/evidence/test-20260809-regression/
```

关键文件：

1. `regression-scenarios.csv`
2. `records/regression-summary.md`
3. `api/`
4. `database/`
5. `events/`
6. `screenshots/`

## 3. 场景台账规则

`regression-scenarios.csv` 固定采用 `REG-01 ~ REG-10`：

1. `REG-01` 创建预付单
2. `REG-02` 提交支付请求
3. `REG-03` 渠道回调成功
4. `REG-04` 支付成功自动清分
5. `REG-05` 清分结果自动结算
6. `REG-06` 清分结果自动记账
7. `REG-07` 跨系统链路诊断
8. `REG-08` 失败派发重试 / DLQ
9. `REG-09` 结算审核与出款
10. `REG-10` 日终处理与运营巡检

每个场景都要回填：

1. `sample_biz_no_or_task_no`
2. `api_status`
3. `db_status`
4. `event_status`
5. `page_status`
6. `rollback_or_compensation_status`
7. 对应证据文件路径

状态说明：

1. `PASS`：当前同批次证据已补齐
2. `HISTORICAL`：只有历史批次证据，可用于说明能力存在，但不能直接作为当前放行依据
3. `TODO`：当前仍未补证据
4. `OPTIONAL / NOT_APPLICABLE`：当前场景不强制要求该类证据

## 4. 审计命令

```bash
node tools/release/audit_regression_pack.mjs \
  --root /Users/abc123/workspace/home-service-payment-system \
  --pack /Users/abc123/workspace/home-service-payment-system/docs/releases/evidence/test-20260809-regression
```

审计会阻断以下情况：

1. 任一场景仍有 `TODO`
2. 场景缺业务编号或任务号
3. 已标记通过但证据文件不存在
4. 回归汇总文档仍有 `TODO`
5. 页面或补偿/回滚仅有 `HISTORICAL` 证据

## 5. 本地自动化基线报告

需要快速复跑某个后端模块并保留可机器消费的摘要时，可使用：

```bash
MAVEN_REPO=/Users/abc123/apache-maven-3.9.16/repository \
JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk1.8.0_202.jdk/Contents/Home \
node tools/release/run_local_regression_report.mjs \
  --only payment-core \
  --skip-frontend \
  --output .runtime/payment-core-current-regression.json
```

报告默认同时覆盖后端回归与 payment-core 的 5 个用户端（API client、App、H5、PC、小程序），并保存后端/用户端/管理端日志路径、测试统计和门禁摘要；使用 `--skip-user-frontend` 可在只关注后端时跳过用户端。它属于本地自动化基线，不替代当前批次页面、补偿运行态、真实渠道、生产中间件或正式发布证据。

## 6. 与版本治理的关系

只有当以下条件同时满足，回归证据包才可以作为 `test -> master` 的一部分证据：

1. 关键后端门禁通过
2. 回归证据包审计通过
3. 页面冻结验收矩阵补齐
4. 补偿、回放、回滚演练拥有最新同批次证据
5. 发布说明、审批、稳定观察和签字结论完整

如果上述任一条件不满足，仍然不能自动合并 `master` 或创建 `release/*`。
