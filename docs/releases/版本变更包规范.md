# 版本变更包规范

## 1. 目标

每个 `release/*` 必须携带一套可独立交付、可审计、可执行的版本变更包。总发布说明用于给出版本结论，专项文档用于让开发、测试、运维和业务能够直接执行。

## 2. 固定目录

```text
docs/releases/<version>/
├── 01-后端变更说明.md
├── 02-前端变更说明.md
├── 03-数据库与接口变更说明.md
├── 04-运维操作手册.md
├── 05-测试与验收报告.md
└── 06-回滚与已知问题.md
```

## 3. 交付要求

1. `01-后端变更说明.md`：模块、接口、状态机、事件、配置、兼容性和代码提交。
2. `02-前端变更说明.md`：端别、页面、交互、权限、异常态、构建产物和验收入口。
3. `03-数据库与接口变更说明.md`：DDL、字段、索引、迁移顺序、API、事件、幂等和兼容策略。
4. `04-运维操作手册.md`：发布前检查、部署顺序、配置项、启动验证、监控、告警和操作权限。
5. `05-测试与验收报告.md`：测试环境、命令、用例、结果、跨系统链路、性能/安全缺口和证据路径。
6. `06-回滚与已知问题.md`：回滚触发条件、代码/数据库/配置回滚、数据修复、已知限制和责任人。

## 4. 门禁

- 六份专项文档必须存在，不能用“见发布说明”替代。
- 文档中的版本号、来源 SHA、发布日期和系统清单必须一致。
- 数据库变更必须标明是否向前兼容，以及回滚是否需要反向脚本。
- 测试报告必须记录真实命令和真实结果，不得只写“已验证”。
- 未解决的 P0/P1 问题必须进入已知问题，并阻断或明确豁免 release。
