# v1.0.0 发布说明

## 1. 版本信息

- 版本号：`v1.0.0`
- 发布日期：`2026-08-02`
- 发布分支：`release/v1.0.0`
- 基线分支：`master`
- 业务基线：`c8e10ce`
- 发布审计基线：`e193185`

## 2. 发布范围

- 涉及系统：payment-core、wallet-system、gateway-access、clearing-system、settlement-system、accounting-system。
- 涉及模块：支付下单与回调、收银台、退款、账单与四项经营导出、支付配置和路由、任务中心、支付事件、钱包、网关、清分、结算、账务，以及 RabbitMQ outbox/retry/DLQ/补偿闭环。
- 不在本次发布范围：生产渠道商户真实密钥、生产 RabbitMQ/MySQL 基础设施开通、生产环境资金迁移与历史数据清理执行；这些须在目标环境按本说明的配置、备份和变更流程单独实施。

## 3. 本次功能清单

1. 完成 payment-core 支付、退款、支付单、账单、收银台会话、支付流水和 bills/cashier-sessions/refunds/payment-flows 四项导出闭环。
2. 建立 payment success -> clearing -> settlement/accounting 的 AMQP 事件链路，覆盖 outbox publisher confirm、消费幂等、TTL retry、专属 DLQ、死信任务 intake、人工复核与定向 replay。
3. 补齐钱包、网关、清分、结算和账务的后台管理与资金基础能力，并提供九端前端入口。

## 4. 数据库变更

1. payment-core 增量迁移：`2026-07-31-ack-legacy-recursive-issue-alerts.sql`、`2026-07-31-add-payment-task-lease.sql`、`2026-08-01-add-payment-dead-letter-task.sql`。
2. clearing-system 增量迁移：`20260801_add_clearing_event_outbox.sql`。
3. 索引与新表以各迁移脚本为准；首次建库按六个系统各自 `schema.sql`，有种子数据的系统再执行对应 `data.sql`。
4. 存量环境必须先备份，再按迁移脚本增量执行；不得用 `schema.sql` 或 `data.sql` 覆盖已有业务库。

## 5. 接口变更

1. payment-core 新增和完善支付、退款、账单、会话、任务中心、事件、路由、配置、监控、日终及结算查询接口，含四项导出下载接口。
2. wallet、gateway-access、clearing、settlement、accounting 分别提供资金账户、网关接入、清分、结算、账务的后台接口；具体请求与响应以各系统 controller 和接口文档为准。
3. 兼容性说明：接口均以新增能力和既有接口扩展为主；发布前必须由调用方按环境地址、认证与渠道配置完成回归，禁止依赖 demo 种子商户配置进入生产。

## 6. 前端变更

1. payment-core：admin-web、app-web、h5-web、pc-web，覆盖运营管理和收银台支付结果链路。
2. 管理后台：wallet、gateway-access、clearing、settlement、accounting 各一个 admin-web。
3. 本版新增或调整页面包含支付/退款、四项导出、支付任务与事件、钱包账户与账本、清分/结算/账务事件管理等；九端均已通过 Vite 生产构建。

## 7. 测试结论

1. 后端测试：payment-core `213`、wallet `5`、gateway-access `8`、clearing `13`、settlement `9`、accounting `10`，合计 `258` tests，均为 `0` failures、`0` errors、`0` skipped。
2. 前端构建：payment-core 四端与其余五个系统 admin 端共九个 `npm run build` 均通过。
3. 联调结论：真实 RabbitMQ 与隔离 MySQL 演练已验证支付成功事件、清分、结算/账务消费、broker 恢复、retry/DLQ、死信任务人工结案、定向 replay 和幂等保护。
4. 未覆盖项：本地隔离环境不能替代生产渠道、生产流量、真实商户资金和生产灾备演练；生产发布需按本说明执行发布后验证与回滚准备。

## 8. 已知风险

1. RabbitMQ 中保留 3 条历史演练 DLQ 副本（clearing 1 条、accounting 2 条）；对应 payment-core 任务均已结案，不是待处理积压，但生产监控应继续排除这三条审计留存并对新增消息告警。
2. 默认 `java` 可能指向 JRE；构建/测试必须使用 JDK 8（本地验证为 Oracle JDK `1.8.0_202`）或目标环境约定的完整 JDK。
3. 渠道密钥、数据库账号、RabbitMQ 凭据和生产回调地址必须经环境配置注入，禁止提交或沿用本地演练配置。

## 9. 回滚说明

1. 代码回滚：将部署版本回退到 `18fdf2d` 前的稳定 master 基线，或回退到发布前经批准的上一版本标签；不得选择性回退跨系统事件消费者而保留新 publisher。
2. 数据回滚：仅对本版增量迁移执行对应回滚/数据修复；先备份 payment-core 与 clearing 事实表、outbox 和补偿任务。禁止在生产直接执行删库重建演练脚本。
3. 配置回滚：恢复各系统 application 配置、渠道路由、RabbitMQ exchange/queue binding 与前端环境变量到发布前版本；确认 outbox 不再向已下线 consumer 路由投递。

## 10. 发布后验证项

1. 核心支付：创建支付单、支付回调、支付状态查询、收银台结果页和 payment success outbox 状态均正确。
2. 资金链路：清分、结算、账务各自产生唯一业务事实；消费者在线，主/retry 队列零积压；新增 DLQ 必须生成可审计任务并按流程处置。
3. 退款与配置：退款申请/回调、渠道配置与路由、任务中心手动重发、四项导出下载均可用。
4. 发布保障：核验数据库迁移版本、监控/日志、前端入口、回滚开关和渠道密钥未使用 demo 值；持续观察错误率、队列积压与补偿任务状态。
