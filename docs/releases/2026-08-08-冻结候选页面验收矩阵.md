## 3. 冻结候选重点状态

页面级验收必须覆盖以下核心状态，不允许只用“处理中”统称：

| 状态 | 说明 |
| --- | --- |
| `PREPAY_CREATED` | 已创建预付单但尚未提交渠道 |
| `WAIT_CALLBACK` | 已提交渠道等待回调 |
| `RISK_REVIEW` | 命中风控复核，禁止继续错误推进 |
| `SUCCESS` | 已成功支付并完成主链路收口 |
| `CLOSED` | 支付单已关闭，不可继续模拟成功回调 |

## 4. 页面验收矩阵

| 页面 | 关键状态/动作 | 当前基线要求 |
| --- | --- | --- |
| `admin-web` 订单中心 | 发起支付、查看支付单、查看收银台 | 必须能从订单进入支付主链路，不出现空跳转 |
| `admin-web` 支付单详情 | `WAIT_CALLBACK / RISK_REVIEW / SUCCESS / CLOSED` | 必须有明确状态表达，且动作按钮与状态一致 |
| `admin-web` 支付流水查询 | 支付提交、回调、事件、路由 | 必须能按支付单号定位主链路轨迹 |
| `admin-web` 支付事件列表 | `PAYMENT_SUCCESS` 出站与处理结果 | 必须能查询支付成功事件与状态 |
| `admin-web` 交易异常中心 | 异常聚合、SLA、处理动作 | 必须能识别主链路异常，不允许页面空洞 |
| `admin-web` 收银台会话 | 会话状态、终端场景、支付单关联 | 必须能回溯当前预付单与支付单 |
| `app-web` 收银台 | 提交支付、状态守卫 | `RISK_REVIEW` 不允许继续错误提交 |
| `app-web` 支付结果页 | `WAIT_CALLBACK / RISK_REVIEW / SUCCESS / CLOSED` | 按钮状态必须与业务状态一致 |
| `h5-web` 收银台 | 状态映射、文案、按钮禁用 | 必须与 `app-web` 保持一致口径 |
| `h5-web` 支付结果页 | `WAIT_CALLBACK / RISK_REVIEW / SUCCESS / CLOSED` | 必须与 `app-web` 保持一致口径 |
| `pc-web` 收银台 | 桌面端展示、返回收银台、状态守卫 | `WAIT_CALLBACK` 和 `SUCCESS` 必须可正确切换 |
| `pc-web` 支付结果页 | `WAIT_CALLBACK / RISK_REVIEW / SUCCESS / CLOSED` | 必须保持桌面端表达完整，不允许简化成移动端残片 |
| `clearing-system` 清分事件页 | 支付成功事件、失败派发重放 | 必须能看到 `publishStatus / retryCount / nextRetryAt / replayHint` |
| `settlement-system` 结算/出款页 | 结算单、出款批次、失败重试 | 必须能承接清分结果后的下游出款事实 |
| `accounting-system` 账务事件页 | 支付成功、清分生成、结算补偿 | 必须能定位事件消费事实和补偿链路 |
