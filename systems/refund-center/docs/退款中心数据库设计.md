# 退款中心数据库设计

数据库：`housekeeping_refund`。

| 表 | 用途 |
| --- | --- |
| `t_refund_payment_source` | 支付成功事实投影，作为退款金额校验依据 |
| `t_refund_order` | 退款主单和状态机 |
| `t_refund_operation_log` | 退款动作审计 |
| `t_refund_outbox_event` | 退款成功事件出站，包含派发状态、重试次数、最近错误信息 |

金额统一使用 `DECIMAL(18,2)`，退款单号、幂等键、日志号均设置唯一约束，状态和支付单号建立索引。

`t_refund_order.terminal_at` 是成功与失败回调写入的终态时间。新库以 `database/schema.sql` 建表；已有 MySQL 库需在受控变更流程中审核并执行 `database/migrations/2026-10-12-add-refund-terminal-time.sql`，不可仅依赖 H2 `backend/src/main/resources/schema.sql`。增量脚本只增加可空列，不伪造历史退款终态时间；迁移后须核对 `SUCCESS`、`FAIL` 中仍无 `terminal_at` 的历史单据并人工确认事实，不能以 `updated_at` 自动回填。

```sql
SELECT status, COUNT(*) AS missing_terminal_time_count
FROM t_refund_order
WHERE status IN ('SUCCESS', 'FAIL') AND terminal_at IS NULL
GROUP BY status;
```

新退款单将原支付渠道写成 `t_refund_order.channel_code` 快照，并以 `(channel_code, channel_refund_id)` 唯一约束渠道退款流水归属；只有存在渠道快照时才能绑定渠道退款号。新库基线与 `database/migrations/2026-10-12-add-refund-channel-identity.sql` 分别服务新建库和已有库，增量脚本只加可空列及唯一键，不推断历史渠道归属。已有库运行新版本前，需人工核查历史 `SUCCESS/FAIL` 且存在渠道号的退款单，以渠道原始回执确认归属和重复占用，再安排受控修复；新增唯一键不会阻止历史空快照行与新行同号，不能以建索引代替这一步。未核实前，历史缺快照单的再次成功回调保持人工核查，不自动补填。

```sql
SELECT refund_order_id, payment_order_id, status, channel_refund_id
FROM t_refund_order
WHERE channel_refund_id IS NOT NULL AND channel_code IS NULL;
```
