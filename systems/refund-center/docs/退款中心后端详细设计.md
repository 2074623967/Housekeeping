# 退款中心后端详细设计

## 1. 目标

独立承载家政服务的逆向交易事实，覆盖退款申请、人工审核、渠道提交、异步回调、失败重试和审计追踪。退款中心不直接修改支付核心、账务、清分、结算数据库。

## 2. 状态机

```text
REVIEWING --审核通过--> APPROVED --提交渠道--> PROCESSING --成功回调--> SUCCESS
                                                       \--失败回调--> FAIL --重试--> PROCESSING
```

所有状态变更都带期望状态条件，重复点击和重复回调不会导致状态回退。

## 3. 分层

- `controller`：请求绑定和响应包装。
- `service`：业务接口。
- `serviceimpl`：金额校验、状态机、幂等和事务编排。
- `dao`：数据访问编排。
- `mapper`：MyBatis 接口。
- `mapper.xml`：SQL、分页、状态条件更新和统计查询。
- `entity`：数据库实体，使用 Lombok `@Data` 和字段中文注释。
- `dto`：接口输入输出对象，字段均有中文注释。

## 4. 关键规则

1. 退款只能针对退款中心已投影的支付成功事实。
2. 单笔支付累计 `REVIEWING/APPROVED/PROCESSING/SUCCESS` 退款金额不得超过原支付金额。
3. 幂等键唯一，重复申请不会产生第二个退款单。
4. 渠道回调只允许处理 `PROCESSING` 状态；同结果的重复回调直接返回当前退款单，不重复写日志、不重复写成功 outbox。
5. `SUCCESS` 事实应写入 outbox，后续由账务和对账系统消费。
6. 真实渠道签名、证书和 HTTP/SDK 调用通过 `gateway-access` 适配，不在退款中心硬编码密钥。
7. 退款成功 outbox 需要保留派发状态、重试次数和最近一次错误信息，便于运营在退款中心直接观察出站链路。
