## 2026-09-23 退款失败补偿操作入口

退款详情页在 `PROCESSING` 状态下新增“模拟失败回调”入口，与既有成功回调并列；失败回调会记录本地渠道超时失败码，进入 `FAIL` 后可继续执行“失败重试”，再回到处理中并完成成功回调。这样本地运营骨架可以从页面覆盖成功、失败和补偿三条状态路径，而不是只能演示成功终态。

验证：退款中心 admin-web `6/6` 测试通过，Vite 生产构建通过；真实渠道回调、验签和资金到账仍未由本地模拟替代。

## 2026-09-23 支付成功事实投影的 MySQL 幂等兼容

发现退款中心支付成功事实投影的 MyBatis SQL 使用 H2 专用 `MERGE INTO`，且应用随附 schema 将 outbox 载荷声明为 H2 专用 `CLOB`，切换到生产 MySQL 时无法直接执行。本轮改为 `INSERT ... ON DUPLICATE KEY UPDATE`，并将共享 schema 的载荷列改为 H2/MySQL 均支持的 `TEXT`；保留 `payment_order_id` 唯一键和重复投影更新语义，MySQL 交付 DDL 仍可使用 JSON 类型。

验证：退款中心后端回归 `18/18` 通过，新增集成用例覆盖同一支付成功事实重复投影后仍只形成一份可退款来源并使用最新客户快照；`git diff --check` 通过。当前仍未连接真实 MySQL 实例，不能把 H2 兼容测试当成生产迁移或运行态证据。

## 2026-09-24 管理端分页响应边界补强

### 本轮修正

1. 退款列表和成功事件列表 API 客户端将数组、`null`、字符串等畸形分页响应统一归一为稳定的 `items / total / pageNo / pageSize` 结构，避免数组索引泄漏或页面继续沿用上一页数据。
