# 预付来源存量只读盘点

`2026-10-05-prepay-source-kind-readonly.sql` 用于盘点 `source_kind = 'UNKNOWN'`、非法来源标记及已标记来源与当前订单行冲突的存量。它只包含会话库选择和四条 `SELECT`：前两条按支付状态、当前订单行是否存在汇总全部未知预付并展示最近 500 条明细；后两条按支付状态及异常类型汇总全部非法标记、`STANDARD_ORDER` 来源消失、`VIRTUAL` 号与现有订单撞号的预付，并展示最近 500 条明细。明细优先列出非终态，再列成功态，不输出客户姓名。

仅在获准的只读账号、限定数据库和评估过负载的窗口执行；先用目标 MySQL 8 的 `EXPLAIN` 核对大表访问开销。两条明细都是**样本而非全量清单**，各自超过 500 行时必须另行设计受控分页/导出，不能据样本量与汇总量不一致推断数据丢失。

`PRESENT_NOW` / `ABSENT_NOW` 和两类 `*_NOW` 冲突只反映查询当时的订单行，不证明预付创建时属于标准订单或虚拟业务。`MISSING_PAYMENT`、金额不一致或同一支付单多预付应先核查关联事实。此文件不执行迁移、`UPDATE`、历史来源推断或资金操作。任何补标需要可信历史凭证、归属复核、受控审批与回滚方案；不能核实的仍保持 `UNKNOWN` 并按业务流程安全处置。

来源值按原始字节精确比较；大小写变化或末尾空字节不是合法来源。目标 MySQL 8 仍需验证比较语义和执行计划，不能把 H2 MySQL 模式回归当作目标库验收。
