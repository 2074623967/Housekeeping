# 第一阶段B-支付交易闭环同类产品对标

## 1. 文档目标

本文档用于从资深产品经理、资深财务架构师、资深后端架构师视角，对 `payment-core` 当前冻结版 V1 与行业成熟支付产品做能力对标。

## 2. 当前版本已达到的行业共性能力

1. 订单、账单、预付单、支付单对象已拆分
2. 收银台参数已标准化组织
3. 后台可查看支付详情与关键轨迹
4. 支持主动查单、回调收口、关闭支付单
5. 为后续账务、清结算提供事件基础

## 3. 当前版本相对成熟产品的差距

### 3.1 产品侧

1. 查询筛选尚未全部后端化
2. 收银台结果反馈仍可继续细化
3. 退款与结算仍未进入完整产品闭环

### 3.2 财务侧

1. 账务分录尚未接入
2. 清分、清算、结算尚未承接
3. 对账差异与补偿机制尚未落地

### 3.3 技术侧

1. 回调验签、防重、冲突收敛仍需增强
2. 主动查单未接真实渠道
3. 定时巡检、补偿任务、告警体系仍需建设

## 4. 对标结论

从公司内开发交付标准看，当前 `payment-core` 已经达到：

1. 可作为正式开发包继续推进
2. 可作为后续系统的上游输入
3. 可作为测试与联调的冻结版基线

从行业成熟支付产品标准看，后续仍应继续补齐：

1. 生产级渠道能力
2. 财务账务能力
3. 监控告警与补偿能力

## 5. 2026-09-23 当前基线复核

前文保留为历史对标判断，不覆盖当时结论。按当前代码、页面矩阵和本地回归证据复核：

### 5.1 已在本地 V1 骨架补齐的能力

1. 产品侧：管理端已覆盖订单、账单、支付单、流水、收银台会话、请求、日志、事件、路由、退款、异常、监控、任务、日终和服务者结算只读入口；App/H5/PC/小程序/API 已具备支付入口、预付单、收银台、结果、查单和关单骨架。
2. 财务联动侧：清分、结算、账务、退款和对账由对应系统承接；受控本地 happy-path 已能生成支付、清分、结算、账务、退款和对账事实，并返回 `COMPLETED`、`4/4`、`financialCloseable=true`。
3. 技术侧：回调验签与 nonce 防重放、支付/退款主动查单补偿、失败事件重发、死信任务、任务租约、监控指标字典和下钻入口均已有代码与自动化基线。

### 5.2 仍属于成熟产品/生产交付差距的能力

1. 微信、支付宝、银行真实协议、生产凭证/密钥托管、真实受理、到账核验和渠道账单仍未接入；本地适配器不构成资金事实。
2. 账务、清分、结算、对账和退款中心的生产 MQ/MySQL、跨系统权限、真实差异处置和财务审批仍需各系统独立证据。
3. 可信身份、字段级权限、真实通知供应商送达、生产压测、当前批次页面/补偿证据和正式发布治理仍未完成。

### 5.3 对标结论更新

当前 `payment-core` 可以作为“正向支付核心域 V1 可运行骨架”和跨系统联调基线继续迭代；不能解释为完整生产支付平台，也不能用本地骨架测试替代真实渠道、资金、审批或发布证据。
