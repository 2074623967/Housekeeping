# 运营配置系统接口文档

基础地址：`/api/ops-config`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/summary` | 查询总览指标 |
| GET | `/agreement-templates` | 查询协议模板 |
| GET | `/business-lines` | 查询业务线 |
| GET | `/payment-types` | 查询支付类型 |
| GET | `/cashier-templates` | 查询收银台模板 |
| GET | `/channel-profiles` | 查询渠道档案 |
| GET | `/routing-rules` | 查询路由规则 |
| GET | `/system-controls` | 查询系统控制 |
| GET | `/effective-snapshot` | 查询当前业务场景的有效配置快照 |
| POST | `/agreement-templates/toggle` | 启停协议模板 |
| POST | `/business-lines/toggle` | 启停业务线 |
| POST | `/payment-types/toggle` | 启停支付类型 |
| POST | `/cashier-templates/toggle` | 启停收银台模板 |
| POST | `/channel-profiles/toggle` | 启停渠道档案 |
| POST | `/routing-rules/toggle` | 启停路由规则 |
| POST | `/system-controls/toggle` | 启停系统控制 |

启停请求示例：

```json
{
  "configCode": "ROUTE_HOME_DEPOSIT",
  "enabled": true
}
```

响应统一为 `{code,message,data,requestId}`，`code=0` 表示成功。

## 有效配置快照接口

### 请求示例

`GET /api/ops-config/effective-snapshot?businessCode=HOME_CLEAN&payType=PAY_CONSUME&terminalType=APP`

### 适用场景

1. `payment-core` 在支付提交前补齐默认支付方式、默认渠道和系统控制项。
2. `risk-control-system` 后续读取大额复核、限额开关等统一控制项。
3. 前端收银台在没有显式下发默认值时，可通过支付核心侧的联动结果获得一致展示。

### 字段说明

| 字段 | 含义 |
| --- | --- |
| `businessCode` | 业务线编码，例如家政保洁、保证金、充值等 |
| `payType` | 支付类型编码，例如消费支付、充值支付、保证金支付 |
| `terminalType` | 当前终端类型，例如 `APP`、`PC`、`H5` |
| `defaultPayMethod` | 收银台默认支付方式 |
| `primaryChannelProfileCode` | 优先渠道档案编码 |
| `backupChannelProfileCode` | 备选渠道档案编码 |
| `routeMatchPolicy` | 当前命中的路由策略说明 |
| `enabledSystemControls` | 当前场景下的统一控制项集合 |

### 快照门禁

1. `businessCode` 对应业务线必须启用。
2. `payType` 对应支付类型必须启用。
3. `terminalType` 对应收银台模板必须启用。
4. `businessCode + payType` 对应路由规则必须启用。
5. 路由规则依赖的主渠道、备选渠道档案必须启用。
6. 任一关键项缺失时，接口直接返回业务异常，不下发半成品快照。
