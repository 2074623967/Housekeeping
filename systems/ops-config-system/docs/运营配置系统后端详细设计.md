# 运营配置系统后端详细设计

## 1. 目标

运营配置系统承接支付平台中偏运营、偏业务编排的配置域，不再继续把协议、路由、收银台模板和支付类型堆进 `payment-core`。

## 2. V1 边界

V1 支持协议模板、业务线、支付类型、收银台模板、渠道档案、路由规则和系统控制的查询与启停。真实渠道证书、密钥、接入权限仍由 `gateway-access` 负责，限额、拦截、风险评分仍由 `risk-control-system` 负责。

## 3. 分层

采用 `controller / service / serviceimpl / dao / mapper / mapper.xml / entity` 标准分层。`serviceimpl` 负责启停编排和异常处理；MyBatis SQL 负责台账查询和状态回写。

## 4. 关键设计

- 协议模板和业务线作为上游配置入口，为收银台、支付路由和签约流程提供统一业务口径。
- 渠道档案只维护渠道台账、退款 SLA、风控标签和商户模板，不维护真实证书。
- 路由规则只沉淀运营编排，后续由支付核心或路由引擎读取并执行。
- 系统控制用于统一维护超时关闭、回调严格模式、大额复核等控制项。
- 启停操作统一使用 `ToggleRequestDTO`，方便后续接审批流和操作日志。

## 5. 后续生产化方向

补齐审批留痕、版本发布、配置快照、灰度发布时间窗、跨系统配置下发、限额配置联动和真实操作审计；在这些能力完成前，V1 仍属于运营配置联调基线。
