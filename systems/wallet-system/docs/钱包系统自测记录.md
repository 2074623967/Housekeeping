## 1. 记录目的

记录钱包系统进入集成测试前的自动化验证结果，避免将“构建通过”误判为资金动作已验证。

## 2. 本轮验证

### 2.1 核心资金动作单测

| 验证项 | 覆盖结果 |
| --- | --- |
| 余额支付成功 | 验证余额扣减、支付单落库、资金流水写入 |
| 余额支付余额不足 | 验证拒绝支付且不创建支付单、不扣减余额 |
| 账户间转账成功 | 验证转出扣减、转入增加、双边资金流水写入 |
| 同账户转账 | 验证拒绝同账户自转，避免无效资金动作 |
| 提现余额不足 | 验证拒绝提现且不创建提现单 |

## 3. 当前边界

1. 本轮覆盖的是服务层余额校验和 Mapper 调用口径，不替代真实数据库事务、并发扣款、幂等键和跨系统事件的集成验证。
2. 钱包系统仍需补充值成功回调、红包资金、风险审批、账户查询和前端构建等门禁后，才能与整包一起进入 `test` 分支。
