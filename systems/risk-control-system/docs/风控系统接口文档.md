# 风控系统接口文档

基础地址：`/api/risk-control`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/summary` | 查询风控总览 |
| GET | `/policies` | 查询风险策略 |
| GET | `/limit-rules` | 查询限额规则 |
| GET | `/blocklists` | 查询黑名单 |
| GET | `/intercept-events` | 查询风险拦截事件 |
| GET | `/review-orders` | 查询人工复核单 |
| GET | `/review-orders/export` | 导出人工复核单快照 |
| GET | `/monitor-rules` | 查询监控规则 |
| POST | `/decisions/evaluate` | 评估支付提交准入决策 |
| POST | `/policies/toggle` | 启停风险策略 |
| POST | `/limit-rules/toggle` | 启停限额规则 |
| POST | `/blocklists/toggle` | 启停黑名单 |
| POST | `/monitor-rules/toggle` | 启停监控规则 |
| POST | `/review-orders/action` | 处理人工复核单 |

启停请求示例：

```json
{
  "configCode": "POLICY_DEVICE_RISK",
  "enabled": true
}
```

人工复核示例：

```json
{
  "reviewNo": "REVIEW-NEW-001",
  "action": "APPROVE",
  "remark": "风控审核通过"
}
```

人工复核动作约束：

1. 仅 `PENDING` 状态复核单允许执行 `APPROVE / REJECT`。
2. 已审核复核单再次提交相同或相反动作时，接口返回业务异常：`仅待审核复核单允许执行审核动作`。
3. 并发审核场景下，以数据库首个成功更新为准，后续请求返回：`复核单状态已变化，请刷新后重试`。
4. 新建复核单内部保存 `v2:` + 无填充 Base64URL SHA-256 上下文摘要（46 字符）；待审和已批准单仅对原来源应用、金额、方式、渠道、商户等请求上下文生效，变更或缺失上下文时失败闭合，不返回 `PASS`。历史空摘要及旧版 64 字符十六进制摘要不能执行 `APPROVE` 或放行，仍可对待审单执行 `REJECT`；重新支付须核实并新建支付单/复核，不得自动回填历史摘要。示例复核号仅用于说明，样例库中的 `REVIEW-1001` 属历史空摘要单，不能批准。
5. 原上下文的待审或已批准复核再次准入时，先核验摘要，再复验当前启用黑名单及策略中的 `INTERCEPT/REJECT` 硬处置；即使先命中其他 `REVIEW` 规则，硬处置仍优先返回追踪事件，不复用旧复核结果放行。人工拒绝维持原拒绝终态；当前只有复核类规则且上下文不变时，待审仍返回 `REVIEW`、已批准仍可返回 `PASS`。审批动作本身不重评策略，实际支付提交以新一次准入结果为准。
6. 同一业务单并发首次命中复核时，新建单按原业务单号精确 SHA-256 键唯一；冲突请求读回胜出待审单并再次核对完整请求上下文，返回相同 `reviewNo`。胜出单上下文不符或已终结时失败闭合，调用方应重新查询/人工核查，不新建另一张复核单。历史空键不自动补齐；该约束依赖受控数据库迁移，风险事件并发去重仍需单独验收。
7. 新风险事件按业务单号、策略、处置结果和有效来源系统的精确组合键唯一；相同组合并发重复插入时核对胜出事件并复用 `eventNo`，不同来源系统不得借用彼此的事件。历史空键不自动补齐，相关唯一性依赖受控迁移；目标 MySQL 8 并发语义仍待现场验收。

支付准入评估示例：

```json
{
  "businessNo": "PAY-RISK-DECISION-001",
  "sourceSystem": "payment-core",
  "sourceAppId": "housekeeping-app-web",
  "sceneCode": "PAY_CONSUME",
  "payScene": "HOME_CLEAN",
  "paymentMethod": "微信支付",
  "channelCode": "wx_h5",
  "merchantNo": "MCH_HOME_001",
  "terminal": "APP",
  "clientIp": "127.0.0.1",
  "clientDeviceId": "DEVICE-99A1",
  "payerPhone": "13800008888",
  "amount": 168.00
}
```

返回结果说明：

- `PASS`：允许继续进入支付渠道提交
- `REVIEW`：生成或复用人工复核单，等待风控审核
- `INTERCEPT`：直接拦截本次支付提交
- `REJECT`：人工复核已拒绝或策略直接拒绝，不允许再次提交

补充说明：

1. 首次准入先检查命中的 `INTERCEPT/REJECT` 硬黑名单和硬策略，再按黑名单复核、`ops-config-system` 有效快照中的 `CONTROL_BIG_AMOUNT_REVIEW`、限额和策略复核顺序判断；启用的大额控制项仅在无硬命中且未命中更优先的复核名单时按阈值转人工复核。
2. 当前控制项读取维度为 `payScene + sceneCode + terminal`，即业务线、支付类型和终端类型组合。
3. `REVIEW` 必须返回 `reviewNo`，`INTERCEPT` 必须返回 `eventNo + hitCode`；`REJECT` 来自人工复核时返回 `reviewNo`，来自策略直接拒绝时生成或复用风险事件并返回 `eventNo + hitCode`，不得返回两类追踪号均为空的拒绝结果。
4. 黑名单或策略命中说明必须与最终决策一致：`INTERCEPT` 表达直接拦截，`REJECT` 表达直接拒绝，不得用“拦截”说明描述拒绝结果。
5. 新建人工复核号和风险事件号分别使用 `REVIEW-`、`RISK-EVT-` 前缀，后接毫秒时间戳及 32 位 UUID 十六进制后缀，长度不超过 64；历史短编号继续可查询/审批，不按新格式拒绝旧记录。唯一键仍是落库最终约束，编号随机后缀不能代替同业务单并发复核去重。
