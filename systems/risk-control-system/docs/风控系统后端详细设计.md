# 风控系统后端详细设计

## 1. 目标

风控系统承接支付平台中的限额控制、危险支付拦截、黑名单、人工复核和交易监控，不再继续由 `payment-core` 的过渡控制页承载完整风控域。

## 2. V1 边界

V1 支持风险策略、限额规则、黑名单、拦截事件、人工复核单和监控规则的查询与治理，并提供人工复核的通过/拒绝动作。真实实时决策、复杂评分模型、流式检测和规则引擎下发仍待后续补齐。

## 3. 分层

采用 `controller / service / serviceimpl / dao / mapper / mapper.xml / entity` 标准分层。`serviceimpl` 负责启停校验、人工复核动作和总览口径；MyBatis 负责风控台账查询和状态回写。

## 4. 关键设计

- 风险策略与限额规则分离，前者负责拦截逻辑，后者负责金额/频次限制。
- 黑名单维护设备、手机号、商家等高风险主体；命中后可直接拦截或转人工。
- 拦截事件只留痕，不在 V1 中重放决策。
- 人工复核单为后续与支付核心、结算系统的人工审核闭环提供基础台账。
- 监控规则负责风险告警阈值和通知策略，为后续接消息告警做准备。

## 5. 后续生产化方向

补齐规则版本治理、审批流、实时决策接口、风控评分、跨系统事件订阅、告警派发、审计日志和 MySQL 实库迁移；在这些能力完成前，V1 仍属于风控治理联调基线。
