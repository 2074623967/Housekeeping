# 清分清算系统后端详细设计

## 1. 系统边界

`clearing-system` 只负责清分规则执行、费用计算、分账结果生成，不负责支付收单和出款执行。

## 2. 服务拆分

### 2.1 `ClearingRuleService`

- 清分规则加载
- 规则版本管理

### 2.2 `ClearingBatchService`

- 批次生成
- 批次重跑
- 批次查询

### 2.3 `ClearingOrderService`

- 单笔清分计算
- 分账结果落库

### 2.4 `FeeService`

- 平台抽佣
- 渠道手续费
- 活动补贴

### 2.5 `ShareService`

- 服务者分账
- 商家分账
- 平台收益汇总

### 2.6 `ClearingEventService`

- 消费支付成功事件
- 生成待结算清分结果
- 支持按 `paymentOrderId` 回查清分结果和分账明细，形成事件追踪闭环

## 3. 技术原则

1. 支付单清分只能执行一次
2. 重跑必须生成新批次或新版本
3. 每笔金额必须可拆解到费用项
4. 所有结果支持审计追溯

## 4. 清分出站确认边界

清分结果出站沿用单 outbox 失败重试模型。HTTP 下游返回 `code=0` 之后，仍复核结算和账务回执事件的清分单号、业务链路、事件类型、消费状态及事件号；配置对账事实时，再复核返回快照中的本清分事实、原支付单、场景和金额。未确认本单归属不标记 outbox 成功，重试可能重放已消费的前序下游，故依赖下游按稳定业务键幂等；不把对账全链收口或 AMQP 发布确认混作下游资金完成。
