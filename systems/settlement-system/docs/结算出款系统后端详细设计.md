# 结算出款系统后端详细设计

## 1. 系统边界

`settlement-system` 负责结算单生成、审核、出款批次和出款跟踪，不负责清分计算。

## 2. 服务拆分

### 2.1 `SettlementBatchService`

- 批次生成
- 批次查询

### 2.2 `SettlementOrderService`

- 结算单生成
- 结算单查询
- 状态流转
- 全量详情下钻：结算单摘要、金额明细、审核日志
- 审核运营闭环：审核通过、审核驳回、日志留痕

### 2.3 `AuditService`

- 审核提交
- 审核通过
- 审核退回
- 审核状态颜色语义统一输出，供前端工作台直接展示

### 2.4 `PayoutService`

- 出款批次创建
- 出款记录更新
- 出款重试

### 2.5 `SettlementEventService`

- 消费清分结果事件
- 生成待结算单
- 支持按 `clearingNo` 回查生成的结算单，形成事件追踪闭环

## 3. 技术原则

1. 结算单按批次生成
2. 审核通过后才能出款
3. 出款失败必须可重试
4. 所有结算动作留审计日志

## 4. 对账事实回执边界

结算消费清分事件后，若启用对账事实地址，先按清分单号、分账目标查回已生成的结算单，再上报规范业务链及净结金额。回执须含本结算事实，否则本次消费失败、由上游重试；已生成结算单依赖既有重复消费一致性校验保持幂等，不把 HTTP 业务成功码等同于本单已登记，也不把对账链路最终完成混作消费条件。
