### 本轮修正

1. `SettlementDataMapper` 新增按 `clearingNo + targetType + targetNo` 查询结算单、按 `eventType + bizNo` 查询结算事件的能力。
2. `SettlementMemoryStore` 在消费 `CLEARING_GENERATED` 前先判断对应结算对象是否已存在结算单，避免重复生成结算单、明细项和结算事件。

2. 当前仍未覆盖真实银行出款回执、自动补偿编排、审批流收口和 MQ 级消费确认，因此仍不触发 `test -> master` 或 `release/*`。

## 2026-08-02 出款草稿与执行分离修正

### 验证结果

| 项目 | 结果 |
| --- | --- |
| 定向后端测试 | `PayoutServiceImplTest` 共 `4` 个用例通过，`0` failures，`0` errors，`0` skipped |
| 后台前端构建 | `npm run build` 通过 |

### 本轮修正

1. `PayoutServiceImpl#create` 改为只创建或刷新待出款草稿批次，不再直接把结算单打成 `已发放`。
2. `SettlementMemoryStore` 新增按结算批次归集待出款草稿的能力，只纳入 `已通过 + 待出款` 的结算单，并复用已有草稿批次与待出款记录。
3. `PayoutsView` 补齐“执行出款”动作，前端流程与后端接口统一为 `创建草稿 -> 执行出款 -> 失败重试`。

### 当前判断

1. 人工发起出款不会再绕过审核直接把未审核结算单标记成 `已出款`。
2. 同一结算批次重复创建出款草稿时，不会重复膨胀待出款记录。

### 临时实例 HTTP 证据

1. `POST /api/settlements/payouts` 在 `SET10001` 尚未审核时返回 `PBT50001`，状态为 `待出款`，金额为 `¥0.00`，未生成出款记录。
2. `GET /api/settlements/orders/SLT20001/full` 仍显示结算状态和审核状态均为 `待审核`，证明创建草稿没有绕过审核直接出款。
3. 后续完整审核、重复建批和执行出款链路已由 `PayoutServiceImplTest` 的 `4` 个 Spring Boot 用例覆盖。
