# gateway-access 后端详细设计

## 1. 目标

提供支付网关接入治理能力，包括应用、渠道、证书和权限。

## 2. 设计原则

1. 接入治理与支付交易解耦
2. 配置优先，当前已使用 MyBatis + H2 持久化实现，后续可平滑切换 MySQL
3. 输出统一接口返回结构
4. 为 `payment-core` 提供真实接入边界

## 3. 第一版实现

1. MyBatis 持久化仓储
2. 统一总览接口
3. 列表查询接口
4. 启停接口

## 4. 后续扩展

1. MyBatis + MySQL 生产化切换
2. 证书版本治理
3. 灰度发布
4. 限流与签名策略

## 5. 2026-07-28 调用方审计增强

1. 新增调用方审计台账，记录应用、网关、操作类型、签名算法、来源 IP、结果和风险提示。
2. 审计查询支持按请求流水号、应用编码和结果状态筛选，便于排查签名失败、停用渠道等接入问题。

## 6. 2026-07-28 环境隔离与灰度发布增强

1. 新增灰度发布路由台账，记录网关在 `PROD / GRAY / UAT` 环境下的发布策略、流量占比和发布时间窗口。
2. 路由台账支持按环境和状态筛选，并支持启停操作，便于发布窗口内快速切流和回退。

## 7. 2026-08-06 启停依赖门禁补强

1. 证书启停不再是孤立开关。启用证书前必须满足两个前置条件：
   - 证书未过期
   - 证书归属网关处于 `ENABLED`
2. 权限启停增加应用依赖校验。若接入应用已停用，则不允许单独启用其权限，避免形成“应用停用但权限恢复”的治理裂缝。
3. 灰度路由启停增加网关依赖校验。若关联网关未启用，则不允许启用路由，避免把灰度流量错误切到停用渠道。
4. 上述门禁全部在服务层显式校验，并通过 MyBatis 实体查询获取依赖对象状态，为后续接入真实审批流、证书轮换流程和发布管控奠定基础。
