# gateway-access 实施说明

## 1. 定位

`gateway-access` 是家政支付平台的渠道接入与技术治理系统。

## 2. 目标

1. 管理接入应用
2. 管理渠道网关
3. 管理证书密钥
4. 管理接入权限
5. 为 `payment-core` 提供真实接入边界

## 3. 第一版范围

1. 接入应用台账
2. 渠道网关台账
3. 证书管理
4. 权限管理
5. 总览看板

## 4. 交付标准

1. 后端可运行
2. 前端可运行
3. 数据库设计已落地并可直接初始化
4. 接口文档可直接给开发使用
5. 可继续扩展证书轮换、灰度发布、限流和验签能力

## 5. 2026-07-25 当前规范状态

1. `dto / entity` 已按统一规范收口到 `Lombok + 中文字段注释` 口径，便于 AI 和开发直接阅读对象定义。
2. `GatewayAccessServiceImplTest` 已验证通过，当前后端骨架在规范收口后仍可正常编译和执行。
3. 后续新增对象时，应继续沿用同一规范，避免子系统之间再次出现风格漂移。

## 6. 2026-07-25 当前治理增强

1. 渠道网关台账已支持按关键字、渠道类型和状态筛选，运营可以先收敛接入排查范围，再做启停操作。
2. 证书管理已支持剩余天数、风险等级和风险提示分层，能直接识别“已过期 / 7天内到期 / 30天内到期 / 正常”。
3. 证书管理页已新增风险等级筛选入口，可按临期等级直接收口待处理证书。
4. 当前 `GatewayAccessServiceImplTest` 已提升到 `6` 个用例并全部通过，`admin-web` 构建通过，说明本轮治理增强已形成可交付基线。

## 7. 2026-09-12 退款尝试身份接入要求

1. payment-core 调用退款提交和退款查单代理时必须提供 `refundAttemptNo`，并确保同一轮提交、失败重发和查单使用同一值；退款终态失败后的新一轮业务重试才使用新值。
2. 每个真实渠道适配必须显式确认 `refundAttemptNo` 到渠道商户退款请求号/查单键的映射，不得退回使用稳定 `refundOrderId` 作为所有轮次共用的幂等身份。
3. 上游调用结果未知时保持 UNKNOWN 并先查单；不得因本地已有尝试号就宣称渠道受理，也不得自动换号再次提交。
4. 当前后端 `50` 项全量测试通过只验证稳定 DTO、校验、透传与审计分支，不替代真实渠道协议、生产凭证、网络白名单、退款到账和财务对账验收。
