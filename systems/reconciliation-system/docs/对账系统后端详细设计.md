# 对账系统后端详细设计

## 1. 目标

把渠道账单和平台支付事实按批次归集，自动输出匹配和差异结果，支持财务人员对差异进行可审计结案。

## 2. 自动匹配规则

匹配主键：`batchNo + paymentOrderId`。

1. 渠道和平台均存在、金额相等、双方状态均为 `SUCCESS`：`MATCHED`。
2. 只存在渠道记录：`CHANNEL_ONLY`。
3. 只存在平台记录：`INTERNAL_ONLY`。
4. 双方金额不一致：`AMOUNT_MISMATCH`。
5. 金额相等但任一状态非成功：`STATUS_MISMATCH`。

## 3. 状态

批次：`CREATED -> RUNNING -> COMPLETED`。

差异：`OPEN -> RESOLVED`。人工结案不删除原始记录，只写入处置结论、备注和时间。

## 4. 生产化边界

- 渠道文件解析应独立为 CSV/Excel/JSON 适配器，并保留原文件摘要。
- 大批量对账应改为异步任务和分片匹配，避免单事务长时间占用。
- 真实环境需要账务、退款和清分事实订阅。
- 差异结案后应通过事件触发责任系统调账或补偿。
