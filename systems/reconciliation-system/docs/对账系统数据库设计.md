# 对账系统数据库设计

数据库：`housekeeping_reconciliation`。

| 表 | 作用 |
| --- | --- |
| `t_reconciliation_batch` | 批次、来源、渠道、匹配汇总和正式对账准入快照 |
| `t_reconciliation_channel_record` | 渠道账单原子记录 |
| `t_reconciliation_internal_record` | 平台支付事实快照 |
| `t_reconciliation_difference` | 差异状态和人工处置 |
| `t_cross_system_fact_snapshot` | 支付、清分、结算、账务统一链路事实快照 |

金额统一使用 `DECIMAL(18,2)`；批次号、渠道流水和支付单号均设置组合唯一约束或索引，保障重复导入可识别。

## 批次准入字段

`t_reconciliation_batch` 新增准入快照字段：

| 字段 | 作用 |
| --- | --- |
| `readiness_status` | `NOT_CHECKED`、`BLOCKED`、`CONDITIONAL`、`READY` |
| `readiness_summary` | 面向财务和运营的准入结论 |
| `readiness_suggested_action` | 下一步处理动作 |
| `readiness_blocking_owner` | 当前阻断责任方 |
| `readiness_chain_count` | 纳入检查的业务链路总数 |
| `readiness_completed_chain_count` | 四阶段事实均完成的链路数 |
| `readiness_abnormal_chain_count` | 存在异常事实的链路数 |
| `readiness_pending_chain_count` | 尚未完成关键事实的链路数 |
| `readiness_checked_at` | 最近检查时间 |

准入快照属于可重算的运营事实，不替代跨系统事实表；批次重新检查时覆盖当前快照，并保留数据库更新时间用于审计。

## 跨系统事实快照

`t_cross_system_fact_snapshot` 以 `business_chain_id` 作为跨系统查询主键，记录来源系统、事实编号、业务编号、事实类型、状态、金额、配置快照版本和发生时间。

唯一键为 `business_chain_id + system_code + fact_type + fact_no`。该表用于跨系统核验和问题定位，不替代支付、清分、结算、账务各自的业务主表。
