# 保证金系统数据库设计

## 数据库

独立数据库：`housekeeping_deposit`。

## t_deposit_account

账户表保存当前余额快照。`account_no` 唯一；`owner_id + owner_type` 唯一，保证一个资金主体只有一个 V1 保证金账户。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `account_no` | varchar(64) | 账户号 |
| `owner_id` | varchar(64) | 主体编号 |
| `owner_type` | varchar(32) | 主体类型 |
| `required_amount` | decimal(18,2) | 应缴金额 |
| `balance` | decimal(18,2) | 总余额 |
| `frozen_amount` | decimal(18,2) | 冻结金额 |
| `status` | varchar(32) | 账户状态 |

## t_deposit_flow

流水表只追加不更新，记录余额和冻结额的前后快照。生产环境按 `account_no + created_at` 查询并按月归档。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `flow_no` | varchar(64) | 流水号 |
| `flow_type` | varchar(32) | 动作类型 |
| `amount` | decimal(18,2) | 发生金额 |
| `before_balance/after_balance` | decimal(18,2) | 余额前后值 |
| `before_frozen_amount/after_frozen_amount` | decimal(18,2) | 冻结额前后值 |
| `reference_no` | varchar(128) | 外部业务关联号 |

完整字段备注和索引以 `database/schema.sql` 为准。

## V2 规划表

V2 不是简单在 V1 表上继续加字段，而是把“账户承载”和“规则归集”拆开，避免后续多品类、多业务线继续耦合。

### t_deposit_total_account

总保证金账户表，承接一个主体的统一资金承载能力。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `total_account_no` | varchar(64) | 总保证金账户号 |
| `owner_id` | varchar(64) | 主体编号 |
| `owner_type` | varchar(32) | 主体类型 |
| `total_balance` | decimal(18,2) | 总余额 |
| `total_frozen_amount` | decimal(18,2) | 总冻结金额 |
| `status` | varchar(32) | 总账户状态 |

### t_deposit_rule_binding

保证金规则绑定表，承接“一个总账户对应多个规则”的多对一关系。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `binding_no` | varchar(64) | 绑定编号 |
| `total_account_no` | varchar(64) | 总保证金账户号 |
| `rule_code` | varchar(64) | 规则编码 |
| `business_line` | varchar(64) | 业务线 |
| `category_code` | varchar(64) | 品类编码 |
| `rule_amount` | decimal(18,2) | 规则金额 |
| `migration_status` | varchar(32) | 结转状态 |

### t_deposit_account_migration

旧账户结转映射表，保证历史余额与流水追溯不丢失。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `migration_no` | varchar(64) | 结转编号 |
| `source_account_no` | varchar(64) | 原账户号 |
| `target_total_account_no` | varchar(64) | 目标总账户号 |
| `source_balance` | decimal(18,2) | 原账户余额 |
| `migrated_balance` | decimal(18,2) | 已结转金额 |
| `migration_status` | varchar(32) | 结转状态 |

### V2 设计原则

1. V1 表保留当前稳定业务闭环，不做破坏性改造。
2. V2 通过新增总账户、规则绑定和迁移映射表承接结构性痛点。
3. 所有历史余额、流水和迁移过程都必须可追溯。
4. 账户展示口径必须与规则口径分离，避免财务和运营口径混淆。
